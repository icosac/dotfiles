# dotfiles

My configs, symlinked into `$HOME`, plus small idempotent scripts to set up a machine.
Supports Ubuntu 18.04 / 20.04 / 22.04 / 24.04, Debian 10 and macOS, tested in CI on every push.

## Quick start

```sh
git clone https://github.com/icosac/dotfiles.git ~/dotfiles
cd ~/dotfiles
./install.sh                          # link configs + base packages
./install.sh ohmyzsh neovim fonts     # ...plus any opt-in setups
```

Run it as your normal user. It calls `sudo` only for package installs. Every step is safe to re-run.

| Command | What it does |
| --- | --- |
| `./install.sh` | link configs, install base packages |
| `./install.sh --link-only` | only link configs (no sudo) |
| `./install.sh --dry-run` | show what would change |
| `./install.sh --list` | list the opt-in setups |
| `./install.sh docker cuda` | also run `setup/docker.sh` and `setup/cuda.sh` |

Each setup can also be run on its own, e.g. `bash setup/neovim.sh`. Most accept `FORCE=1` to reinstall.
Output is logged to `~/.cache/dotfiles/install.log`.

## How it works

- **`config/`** holds exactly one copy of each config, laid out as it is in `$HOME`.
  - `install.sh` symlinks each file into place, so editing `~/.zshrc` edits the repo.
  - Anything already at the target is moved to `~/.dotfiles-backup/<timestamp>/`.

  | Repo | Linked to |
  | --- | --- |
  | `config/zsh/.zshrc` (+ `zshrc.d/*.zsh`) | `~/.zshrc` |
  | `config/git/.gitconfig` | `~/.gitconfig` |
  | `config/tmux/.tmux.conf` | `~/.tmux.conf` |
  | `config/nvim/.config/nvim` (AstroNvim) | `~/.config/nvim` |
  | `config/kitty/.config/kitty` | `~/.config/kitty` |
  | `config/latex/.latexmkrc` | `~/.latexmkrc` |
  | `config/vscode/{settings,keybindings}.json` | VS Code user dir |
- **`packages/`** lists the base packages.
  - `apt.txt` applies to every apt system.
  - `apt-<VERSION_ID>.txt` adds packages, or removes them with `!name`, for one release.
  - `brew.txt` is for macOS.
- **`setup/`** holds the opt-in installers:
  - oh-my-zsh, neovim, fonts, kitty, VS Code
  - ssh keys, git identity
  - docker, CUDA, LaTeX, Regolith, ROS 2
  - tmux plugins, GNOME tweaks, brew cron

  Each one checks the OS and skips cleanly where it doesn't apply.
- **`lib/`** holds the shared helpers: `link`, `pkg_install`, `apt_repo`, OS detection.
- **`vendor/ros2_setup_scripts`** is the [Tiryoh/ros2_setup_scripts_ubuntu](https://github.com/Tiryoh/ros2_setup_scripts_ubuntu) submodule.
  - `setup/ros2.sh` fetches it on demand.
  - In zsh, run `ros2env` to source ROS 2.

## Private and machine-specific settings

Nothing personal is committed. Keep it in these files, which live only in `$HOME`:

- `~/.gitconfig.local`: git `user.name` / `user.email`.
  - `./install.sh` moves it there from an existing `~/.gitconfig`.
  - Otherwise `./install.sh git-identity` asks for it.
- `~/.zshrc.local`: machine-specific shell settings.
- `~/.ssh/config.d/dotfiles`: generated by `./install.sh ssh-keys`.

`./install.sh` also turns on a pre-commit hook (`.githooks/pre-commit`). It refuses commits that add email addresses, `/home/<user>` or `/Users/<user>` paths, or private keys. If a hit is fine, bypass it with `git commit --no-verify`.

## Notes

- **VS Code:** `settings.json` is a symlink into the repo.
  - If you use Settings Sync, turn off syncing *Settings* and *Keybindings*, or the two will fight.
  - `config/vscode/extensions.txt` is installed by `./install.sh code`. Refresh it with `code --list-extensions > config/vscode/extensions.txt`.
- **Neovim** goes to `/opt/nvim`, symlinked as `/usr/local/bin/nvim`.
  - On old glibc (Ubuntu 18.04) the build comes from `neovim/neovim-releases` automatically.
  - Upgrade with `FORCE=1 bash setup/neovim.sh`.
- **ssh:** `chsh` and `ssh-keygen` need a terminal. They're skipped, with a hint, when there isn't one.
- **Testing:** `tests/container-test.sh` runs the full install twice in a fresh container and checks that the second run changes nothing:

  ```sh
  docker run --rm -v "$PWD:/src:ro" ubuntu:24.04 bash /src/tests/container-test.sh
  ```
